## 1. What this phase is, and is not

Spec: `PROJECT_PLAN.md` §4 row 4 is the only spec: *lock today's behaviour before
changing it*. Exit criterion: **a golden set of ≥40 sequences with recorded motif-era
outputs; any later engine change shows as an explicit diff, not a silent drift.**
Coverage list: `PROJECT_PLAN.md` §5 (secreted, membrane, cytoplasmic, mitochondrial,
chloroplast, Gram+, Gram−, multi-label, ambiguous, edge cases). Nothing beyond that
row and that list is in scope.

**Decision (operator, 2026-10-02): every served prediction comes from a real trained
model, never the motif engine.** So this golden set is a **regression harness that
locks the motif engine's current behaviour** so that Phase 14 can swap the engine and
show the difference. It is **test-only, lives under `backend/tests/golden/`, and is
never served.** It makes no claim that the motif engine is right: it records what the
engine *does*.

Hosting is undecided (ADR-0007 §3.3). This phase needs no memory or host number and
records none.

## 3. How a change shows up

Float tolerance: **absolute 1e-6**. Every float the engine reports is rounded before it
leaves the engine; measured over all 35,301 recorded floats, the most decimals any has
is **4** (smallest quantum 1e-4). A real change moves a value by at least one quantum,
100× the tolerance, so the tolerance absorbs representation noise and nothing a real
change could produce. It is itself written in the file header, so changing it requires a
regeneration. Integers, strings, booleans and `None` compare exactly. A field added to
or removed from the output is a difference.

Failure format, from the mutation check in §4:

```
golden mismatch for secreted_enzyme (origin=gallery, group=eukaryote): 23 difference(s)
    output.localization[LYS].probability: 0.078 -> 0.0781 (delta +0.0001)
    output.localization[EXT].probability: 0.8134 -> 0.8143 (delta +0.0009)
    ...
engine identity / TRUST (tau, temperature) differs from the recording:
    engine.config_hash: "566f320a4704" -> "8f263d75453d"
    trust.tau: 0.67 -> 0.66 (delta -0.01)
```

Regeneration is never automatic (no test, hook or CI step calls it):

```powershell
cd C:\Users\saika\protloc-fusion
python scripts\regen_golden.py            # compare only; exit 1 if stale, writes nothing
python scripts\regen_golden.py --write    # print the summary, then overwrite
```

## 5. What Phase 14 does with this

Swap the engine, run `pytest tests/golden`, read the diff. Do **not** blindly
`--write`: the old file is the baseline. Copy it to `golden_set_motif.json` first if the
motif-versus-model comparison is wanted in the eval report. The coverage test reads only
the file, so it keeps passing after the swap; if a regenerated file loses a derived
category (a model that never abstains has no `ambiguous` entries), that test fails on
purpose.

## 6. Deviations — decide if you disagree

1. **Fourth origin value, `synthetic`.** The brief listed `gallery` / `engineered` /
   `real`. The 23 fresh generator sequences are neither gallery nor edits of one, so
   they carry `synthetic`. `engineered` is kept for documented edits.
2. **Extra category `other_compartment`** for nuclear, ER, peroxisomal, periplasm and
   surface entries that §5 does not list. It is not counted toward any §5 requirement.
3. **Rejected inputs are entries** whose recorded outcome is the `ValueError` message

   shows as a diff too.
4. **Only `service.predict` is locked.** `scan`, `triage`, `landscape` and the HTTP
   layer are not in the golden set; the row asks for recorded outputs of the engine, and
   `predict` is the seven-part result. Say if you want the scanner locked as well.
5. **One inline `noqa: S311`** (non-cryptographic seeded RNG, `golden_inputs.py`). No
   config exemptions were added.
