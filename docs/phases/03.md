# Phase 3 — Widen the frozen contract for model-backed, calibrated output

**Status:** complete on branch `phase/03-contract-provenance` — not pushed, not tagged · **Track:** MVP (mandatory) · **Budget:** 2.5 h
**Depends on:** Phase 1 (git + CI green), Phase 2 (hosting decided, ADR-0005 superseded)
**Unblocks:** Phases 9, 10, 14, 16 — every phase that returns a model-produced number

---

## 1. Why this phase exists

The five screens currently render output from the motif engine. Over Phases 9–14 each
field is replaced, one at a time, by a trained model's output. Those two sources differ in
ways the UI must show rather than hide: a model probability is calibrated and has a
tuned per-label threshold, a motif score has neither.

If the contract is widened once, now, additively, then every later phase ships a
model-backed field by flipping `source` from `"motif"` to `"model"` — no schema change,
no frontend break, no half-migrated state where the user cannot tell which engine
answered. If it is widened later, each of Phases 9–14 carries its own breaking change and
the five screens break five times.

This is the cheapest phase in the plan and the one with the widest blast radius.

---

## 2. Scope

**In scope**
- Additive fields on every prediction-bearing schema in `backend/protloc/domain/contracts.py`
- Regenerated `docs/api/openapi.yaml` and `frontend/src/types/api.generated.ts`
- A provenance badge and a "no confident call" state in the UI, wired to the new fields
- Round-trip and backward-compatibility tests

**Out of scope**
- Any model, any training, any calibration maths — Phases 7–10
- Changing endpoint paths, verbs, status codes or the 202-then-poll pattern (ADR-0001)
- Removing or renaming any existing field

**The additive rule.** Every new field is optional with a default that reproduces today's
behaviour. A client written against the pre-Phase-3 contract must keep working against
the post-Phase-3 API. That is what makes this phase safe to do before the models exist.

---

## 3. The fields

Per prediction-bearing field (localization labels, membrane type, sorting signal,
cleavage site, transit peptide, GO terms, homology verdict):

| Field | Type | Default | Meaning |
|---|---|---|---|
| `source` | `Literal["motif","model"]` | `"motif"` | Which engine produced this number. The UI must show it. |
| `threshold` | `float` | `0.5` | The decision threshold actually applied to this label. Per-label and MCC-tuned once Phase 10 lands, not a global 0.5. |
| `calibrated` | `bool` | `false` | Whether a fitted calibrator was applied. A raw sigmoid is not calibrated and must not be displayed as if it were. |
| `confidence_band` | `Literal["high","medium","low","none"]` | `"none"` | Coarse band for the UI. `"none"` means below τ — the system is abstaining on this label. |

Top-level on the result object:

| Field | Type | Default | Meaning |
|---|---|---|---|
| `no_confident_call` | `bool` | `false` | True when no label clears its threshold. The screen then says so instead of showing the argmax. |
| `calibration_version` | `str \| null` | `null` | Identifies the fitted calibrator; `null` while uncalibrated. |
| `threshold_policy` | `Literal["fixed","per_label_mcc"]` | `"fixed"` | How thresholds were chosen, so the Trust Console can state it. |

`model_version`, `config_hash`, `rules_version` and `experiment_id` already exist on every
response and stay as they are.

### Why `no_confident_call` is a first-class field

DeepLoc 2.1 forces at least one membrane-type label on every input, which means it cannot
express "this protein is not a membrane protein" and a reviewer cannot distinguish a
confident call from a least-bad guess. Making abstention an explicit boolean rather than an
absence of labels is a small schema decision that the Trust Console turns into a real
claim about the system, and it is one of the few places this project can be straightforwardly
better than the tool it is compared against.

## 6. Risks

| Risk | Why it bites | Mitigation |
|---|---|---|
| A field is added as required rather than optional | Every existing test and the frozen spec break at once; the phase stops being 2.5 h | Review the diff for any new field without a default before committing |
| `threshold` is read as "the global τ" | Phase 10 produces one threshold per label; a single global value bakes in an assumption that has to be unpicked later | Field lives on each label, not on the result object. The Trust Console reads `threshold_policy` to know which regime is active |
| The generated spec is hand-edited to make CI pass | The next build silently reverts it, and the frozen contract stops being the source of truth | CI diffs the regenerated file; a hand edit fails the build rather than passing it |
| `confidence_band` becomes the thing the UI shows instead of the number | A coarse band reads as more certain than the probability behind it | The band styles the row; the probability stays visible as the datum. Already the rule in `docs/DESIGN.md` |
| Scope creep into calibration | "While I'm here" turns a 2.5 h phase into Phase 10 | No calibrator is fitted in this phase. `calibrated` is `false` everywhere when it closes, and that is the correct result |

### Deviations from the spec text — decide if you disagree

1. **`threshold` has no literal default.** The spec says default 0.5. CLAUDE.md calls a
   literal 0.5 a bug, and the engine's tau is 0.67, so 0.5 would misreport every legacy
   payload. A payload without `threshold` reads it from its own `abstention_threshold`
   (a `before` validator). Consequence: `threshold` is *required* in the response schema.
2. **The service emits the tau it applied (0.67), not 0.5**, for the same reason.
3. **`calibrated` is `false`** although the demo temperature-scales on a synthetic split:
   no calibrator exists in the contract's sense. The Inspector no longer says "calibrated".
4. **`confidence_band` above the threshold** splits `[threshold, 1]` in thirds. The spec
   gives no cut-offs; this adds no free constant and is a placeholder until Phase 10.
5. **`threshold` is per task, not per label**, in the contract's `TaskPrediction`
   (per label only in the demo `localization` rows). A multi-label head with per-label
   MCC thresholds needs a `label_thresholds` map. Cheap and additive, but not in the spec:
   decide before Phase 10.
6. **No `source` on the homology verdict** (the spec lists it): its engine is a k-mer
   reference search, and `motif`/`model` is the wrong vocabulary for it. Phase 13 decides.
7. **Two shapes.** The five screens consume the demo dicts from `app_v2`, not the Pydantic
   contract; the contract has no mapper from them. The fields were added to both. The
   fixtures' demo-to-contract mapping is test-only and is the seed of Phase 14.
8. The plan docs on `phase/02-hosting` were uncommitted; they are the first commit here.
