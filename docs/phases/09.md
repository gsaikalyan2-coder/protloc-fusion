## 3. Facts measured

- Partitions 1-4 hold 146 + 77 + 93 + 92 = 408 subset accessions; partition 5 holds 99. Several
  classes have very few positives per fold (test support: lysosome/vacuole 2, plastid 2, peroxisome 4).
- The pooled validation MCC is defined for all ten classes (every class has at least 2 positives);
  on test no class falls below 2 positives, so none is marked undefined.
- The 16 grid points span mean fold macro F1 0.341 to 0.481; the chosen point (0.481) is the maximum of that range.
- The holdout macro F1 used for early stopping (0.47-0.69) is much higher than the out-of-fold
  validation F1 (0.42-0.53 per fold): thresholds tuned on the same small holdout are optimistic (ADR-0011 §4).

## 4. Leakage and protocol checks

- Before every fit the cluster sets of the fit rows, the early-stopping holdout, the validation rows and
  the test partition are asserted pairwise disjoint (`assert_no_overlap`); the final refit asserts train vs test.
  Unit tests make a shared cluster raise before any fit starts.
- The loss weights are computed from the fit rows only; a unit test intercepts the call.
- Partition 5 is read once, by `--evaluate --test`, after the manifest was written and re-checked
  (`check_head_manifest`) and after the weights hash was matched.
- `head.py --check` passes (no data bytes needed).
- The 500 sequences are the same ones the floor uses (same `sequences_sha256`), resolved by one shared
  helper (`protloc.training.subset`).

## 8. Deviations

1. **Focal loss with gamma in the grid** (your gate C choice), where the prompt named BCE with pos_weight; `gamma = 0` is exactly that
   loss and it is what the grid chose.
2. **A per-residue cache was added** (ADR-0011 §2.3, amending ADR-0009 §2.7): Phase 7's pooled cache cannot feed an attention head.
   New modules `protloc/data/residue_cache.py` and `TorchEncoder.embed_residues`, and `embed.py --residues`.
3. **Early stopping on an inner whole-cluster holdout** (your gate B choice), not on the validation fold.
4. **`protloc/training/subset.py`** (shared subset resolver) and a small refactor of `scripts/baselines.py` to use it;
   `protloc/training/head_net.py` holds the torch half so `head.py` stays importable without torch.
5. **No `nn.Module` subclass**: the model is a plain class around `ModuleDict` (strict mypy without torch stubs).
6. **Deterministic `Shuffler`** (SHA-256 ranks) instead of `random.Random`, because the lint rules forbid `random` and no exemption was added.
7. **`--smoke` runs** (every 4th row, 2 epochs) tested the code; no number from them appears here.
8. **The floor needed `--subset`** and undefined-class marking (commits `225948f`, `e0d106c`); the Phase 8 manifest is untouched.
9. **Stages ran on one machine** (Windows); my sandbox checked the code with torch 2.14.1+cu130 on Linux, which produced no reported number.

## 9. UNVERIFIED

- That the head or the floor generalises beyond 500 sequences; every claim here is subset-only.
- That the head would beat the floor with the full 33,461-sequence cache; not run.
- Bit-for-bit reproducibility on another machine or thread count (one run, one machine; torch deterministic flags were on).
- Seed variance: one seed (20260909) only.
- The DeepLoc targets themselves, and any claim of parity with DeepLoc.
- Why validation (0.476) and test (0.366) differ so much; only the numbers were measured. Selection on the same folds,
  the small test partition and different class mixes are candidates, none tested.
- That nested thresholds are leak-free in the strict sense (ADR-0010 §4).
- Docker, GitHub Actions and the frontend gate: nothing there changed and none was run.
