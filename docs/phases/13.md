## 4. Leakage and protocol checks

- Planted self-hit (by accession and by hash), planted same-cluster hit and planted same-partition hit are removed (`test_homology.py`); an unregistered query or an unknown hit target is an error.
- The hit filter is tuned on partitions 1-4 only (leave-one-partition-out, nested thresholds); partition 5 was not read before `--freeze`; the one test run recorded `touches: 1`; a second run printed `refusing: the manifest has problems or the test partition was already scored`.
- The Phase 12 model arms are rebuilt from the saved out-of-fold and cross-fitted scores and match the frozen `go_metrics.json` values (max absolute difference 0.0, tolerance 1e-9). On test they are copied from `go_metrics.json`; the GO head was not re-run, so its touch count stays 1.
- `--check` (no data bytes): `ok`; MMseqs2 18-8cc5c; 108 grid points; the four masks; earlier touches {localization 1, crf 1, go 1}; the manifest and the bundle verify.

## 7. Freeze

`registry/evidence_homology/0.13.0/bundle.json` (`bundle_sha256` `3f6167b7b19a3c15dcbc9d3f008939952151105cdb57615c4a086f07f5231cec`) binds the database pin, the engine pin, the index file list (name, bytes, SHA-256 per file) and `index_sha256`, the GO source hash, ontology hash and vocabulary hash, the selected hit filters, the four masks,
the transfer rule, `source: "homology"` and the independence flags (all `false`). `load_evidence_bundle` refuses a changed index byte, a missing index file, a different GO source or ontology hash, a tampered bundle, a mask list other than the four, and an independence flag that is not `false` (unit-tested).
`bundle.json` and `data/manifests/homology_metrics.json` are committed; `--freeze` refuses to overwrite them. The index, FASTA and hit files live in gitignored `data/evidence/`.

## 8. Deviations

1. **`createindex` failed once (Gate D)** and was fixed after your answer: the Windows release has no `sh.exe`; `scripts/homology.py` copies `busybox.exe` to `sh.exe` beside `mmseqs.exe`, refuses anything that is not a byte copy, and records `busybox_sha256` with the index. Two reruns were lost to my code not having synced to your disk; the third ran.
2. **Unregistered database sequences are not masked by cluster or partition** (they have neither); the registry-only arm and the identity bins are the diagnostic. The true size of the leakage this allows is not measured.
3. **GO terms for hits come from the corpus `DR GO` lines**, not a GAF download (Gate B); the GOA release is recorded as "embedded in Swiss-Prot 2026_03".
4. **The best-hit and registry-only arms freeze thresholds at the scale of the tie-break prior** (0.0051, 0.0043), so those arms also call terms through the prior.
5. **Latency is per process set** (createdb + search + convertalis) with the index loaded each time; a resident server was not measured.
6. **`data/evidence/_stage_code.tgz`** is a staging archive I made to copy code to a cloud checkout; it is in gitignored `data/evidence/` and I cannot delete it without a Gate E question. Delete it when convenient. Failed `createindex` attempts also left empty `data/evidence/tmp_index/*` folders.
7. **The refuse-to-start check and API wiring are deferred to Phase 14** (Gate F).
8. **`--smoke` runs** tested the code on real data; no number from them appears here.
