DECISIONS MADE

  Apache-2.0 for the project. The patent grant matters for a method paper, and
  no restricted dependency contributes source, so the grant is accurate.

  LAYER DEPTHS — READ THIS BEFORE ADDING A MODULE. test_layering.py assigns each
  of the 17 modules a depth. A module may import only a STRICTLY DEEPER one.
  Equal depth is a violation too, so two pipeline stages cannot import each
  other and `inference` stays the only module that knows the pipeline order.

      0    api, web, jobs, evaluation, training
      10   inference
      20   features, data
      30   models, registry
      40   calibration, consistency
      50   interpretability, evidence
      90   config, utils
      100  domain

  Additional rules, enforced separately from depth:
    - domain imports nothing from protloc.
    - NOTHING imports training. It is an entry point, not a dependency.
    - api, web, jobs may import only {domain, inference, config, utils}.
    - evaluation may import only {domain, config, utils} — it reaches the system
      over HTTP so that the paper's numbers are the user's numbers.
    - Adding an 18th module fails test_every_module_has_a_declared_depth until
      its depth is declared. That is deliberate: a new module is a decision.

  THREE DEVIATIONS FROM FOLDER_STRUCTURE.md, kept deliberately (the alternative
  was an exemption list, which would have weakened the test):
    1. `training` sits at depth 0 as an entry point, not at L3 beside `models`.
       At L3 it could not import features or data, which it must. Depth 0 plus
       "imported by nothing" enforces the rule that actually matters.
    2. `config` and `utils` sit at depth 90, importable from anywhere.
       FOLDER_STRUCTURE places config at L1; at L1, features and evidence could
       not read their own paths from it.
    3. `evaluation` is depth 0 with an allowlist, not a support module.

  CONSEQUENCE PHASE 10 MUST KNOW: interpretability (50) may NOT import models
  (30). Per-residue attribution receives the scored model through a port
  protocol in domain/. This is the documented hexagonal design, but it is a real
  constraint and it is cheaper to know now than mid-phase.

  Severity is note / warning / blocking, from docs/DESIGN.md §3.3 — not
  info/warning/error. The three levels have distinct behaviour: blocking forces
  abstention on the affected task. The wire values are stored in manifests, so
  renaming one is a migration.

  React only. CLAUDE.md now forbids any CSS framework, component library or UI
  runtime beyond React; scripts/check_frontend_deps.py enforces it with an
  allowlist that carries each dependency's reason.

  mypy gates domain and config (PHASE_01 §5 check 4). CLAUDE.md says domain and
  inference. Resolved in favour of the phase file because inference/ is empty;
  WIDEN THE GATE TO inference/ IN PHASE 7, when it first has code.
  The CI step must run from backend/ — see KNOWN GAPS.

  Hydra: hydra-core 1.3.6 is pinned into the dev extra ONLY. The phase file caps
  Phase 1 dependencies, but that cap names the ML stack; the config tree is
  worthless unproven. Consequence: Dockerfile.serve has no hydra, CI can prove
  the tree composes, and Dockerfile.train gets it via [dev].

  Scheduled config values are `???` (OmegaConf MISSING), never a plausible
  default. `${oc.env:X,???}` was tried first and silently resolves to the STRING
  "???" — exactly the invented-number failure PROJECT_PLAN §7.2 guards against.
